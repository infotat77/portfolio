macのストレージを自動で整理するクリーンアップスクリプトを作った話

キャッシュ・スクリーンショット・古いインストーラーが気づけば数十GBに。 Shell Script + cron + .command ファイルで「毎週自動＆手動ワンクリック」の両立を実現しました。 初回実行で約 45GB を節約。その後 PC 内を精査し削除対象を 5 → 10 ステップに拡張、累計 ~120GB 節約。

なぜ作ったのか

ある日 Mac のストレージを確認したら、気づかぬうちにキャッシュだけで 11GB、 campfire 動画の出力が 25GB、Downloads フォルダが 20GB に膨れ上がっていた。 手動で整理するのは面倒だし、整理したことを忘れてまた溜まる。 「整理する」という行為自体を自動化することにしました。

設計の要件

  • 毎週自動実行 — 意識しなくても週1でリセットされる
  • 手動でもワンクリック実行 — 「今すぐ消したい」ときに手間なく動かせる
  • ログが残る — 何をどれだけ削除したか後から確認できる
  • 安全な対象だけ — 再生成できるキャッシュや古いインストーラーのみ。プロジェクトファイルは触らない

削除対象の設計（v2：9ステップ）

対象理由
Desktop のスクリーンショット（.png・.mov）撮ったその場で確認し終わることがほとんど。画面収録も同様に溜まりやすい
~/Library/Caches（ユーザー系）Google・pip・npm・Homebrew などアプリが自動再生成する
アプリの ShipIt キャッシュ（*.ShipIt/）VSCode・Claude Desktop などのアップデート残骸。更新のたびに ~1GB 規模で溜まる
Downloads の古い .dmg（30日超）インストール済みならインストーラーは不要
Downloads の .dlf バックアップアプリの自動バックアップ。古いものは価値がない
campfire 投稿済み動画（1日以上前）＋孤立サムネイルYouTube にアップ済みの ~5GB/本 を自動削除。対応する動画のないサムネイルも除去
note-generator の output（7日以上前）投稿済み記事・サムネイル画像は手元に置く必要がない
ゴミ箱削除済みのはずなのに容量を占有している
cleanup_cron.log の整理毎週追記のため放置すると肥大化。直近 90 日分だけ保持

システムの Apple 系キャッシュ（CloudKit・HomeKit など）は権限で保護されているため対象外。 ユーザーが作ったプロジェクトファイルには一切触れません。

スクリプトの構成

スクリーンショット削除 → Caches クリア → ShipIt 削除 → 古い DMG 削除 → .dlf 削除 → campfire 動画削除 → note output 削除 → ゴミ箱を空に → ログ整理・保存 
#!/bin/bash
LOG="$HOME/cleanup_log.txt"
FREED=0

# 各ステップで削除前後のサイズ差を計測して合計
BEFORE=$(du -sm ~/Library/Caches/ | cut -f1)
for d in Google pip Homebrew node-gyp ms-playwright Adobe; do
    rm -rf ~/Library/Caches/"$d"/ 2>/dev/null
done
AFTER=$(du -sm ~/Library/Caches/ | cut -f1)
FREED=$((FREED + BEFORE - AFTER))

# 最後にサマリーをログへ
echo "完了！合計 約${FREED}MB 節約" | tee -a "$LOG"

ワンクリック実行：.command ファイル

cron は自動実行の仕組みですが「今すぐ消したい」ときに crontab を操作するのは手間です。 macOS の .command ファイルはダブルクリックでターミナルを開いてスクリプトを実行できます。 Desktop に置けばアイコン一発でクリーンアップが走ります。 

#!/bin/bash
# 🧹 Mac クリーンアップ.command
bash /Users/tatsuya/cleanup.sh
echo ""
echo "何かキーを押すと閉じます..."
read -n 1

cron で毎週自動実行

crontab -e で以下の1行を登録するだけ。毎週日曜の 9:00 に自動実行され、 結果は cleanup_cron.log に追記されます。 

0 9 * * 0 /bin/bash /Users/tatsuya/claude-work/cleanup.sh >> /Users/tatsuya/claude-work/cleanup_cron.log 2>&1

初回実行の結果

~120GB 累計節約容量
週1回 自動実行（日曜9:00）
11steps クリーンアップ対象

初回（2026-05-31）：キャッシュ 11GB・campfire 動画 25GB・Downloads 整理・アプリ残骸などを合わせて約 45GB を節約。 以降は毎週日曜に自動実行されるため、意識しなくてもストレージが管理された状態を保てます。

v2 アップデート（2026-06-06）

PC 内を改めて精査し、削除対象を 5 → 9 ステップに拡張。新たに約 26GB を節約しました。

  • ShipIt キャッシュ削除 — VSCode・Claude Desktop などのアップデート残骸（合計 1.6GB）を毎回削除
  • campfire 投稿済み動画の自動削除 — YouTube アップ済みの動画（~5GB/本）を 1 日後に自動削除。孤立サムネイルも同時に除去
  • note-generator output の自動削除 — 投稿済み記事・画像を 7 日後に削除
  • 画面収録（.mov）の削除追加 — スクリーンショットと同じタイミングで Desktop の画面収録も削除対象に
  • cron ログのローテーション — cleanup_cron.log を直近 90 日分だけ保持して肥大化を防止

削除対象は「使い終わったら自動で消えるべきもの」を基準に選定。 判断が必要なもの（学習データ・開発用 node_modules など）は自動削除せず、手動で判断する運用を維持しています。

v3 アップデート（2026-07-02）

Mac 全体のパフォーマンス改善と campfire クリーンアップのバグ修正を行い、さらに約 50GB を削減。削除対象を 10 ステップに拡張しました。

Mac パフォーマンス改善

  • Adobe Creative Cloud 9デーモンを完全無効化 — LaunchAgents・LaunchDaemons 合計9件を unload。起動時から常駐していたバックグラウンドプロセスを排除
  • Spotlight インデックス修復 — unknown indexing state エラーを解消し mdutil -E で再構築。mds プロセスの暴走が解消
  • 開発フォルダを Spotlight 除外 — node_modules・.git・dist・build・.vscode/extensions・.npm などに .metadata_never_index を設置。mdworker が大量のコードをインデックスしなくなる
  • [9] Spotlight 除外メンテナンスを自動化 — 毎週日曜 9:00 に新規作成された node_modules 等を自動で除外対象に追加

campfire クリーンアップの修正・強化

  • ログ参照バグを修正 — スクリプトが campfire_auto_post.log（6月で止まった旧ログ）しか見ておらず、動画が全件スキップされていた。campfire*.log 横断検索に修正し、今後ログ名が変わっても追従
  • .srt 字幕ファイルを削除対象に追加 — 動画削除時に対応する字幕ファイルも同時削除。残留 .srt も対象
  • [6b] _tmp 中間ファイルの自動削除 — 動画生成の処理中間ファイル（norm_0.mp4〜・merged.mp4 等）が _tmp/ に 27GB 放置されていた。毎週9時に前日分が完成済みのタイミングで自動削除
  • [6b] campfire ログ整理 — stderr.log（96MB）を直近1万行に切り詰め、古いローテートログ・旧 campfire_auto_post.log を削除

その他

  • Downloads のスクリーンショットも削除対象に — [1] のスクリーンショット削除に ~/Downloads を追加
  • 今回の手動削除実績 — campfire 動画 ~16GB・_tmp 27GB・Adobe ログ 1.4GB・Chrome Service Worker 3.4GB・Claude Desktop キャッシュ 720MB など合計 ~50GB を削除

v4 アップデート（2026-07-19）

PC 全体を再スキャンし、cleanup.sh の対象外だった残骸を発見・削除。[2b] を新設して IDE キャッシュの定期整理を自動化しました。

  • Adobe GrowthSDK 残骸（404MB）を削除 — Creative Cloud 無効化後も Group Containers に残っていたデータを一掃
  • Tweetie2 残骸（114MB）を削除 — 廃止された Twitter クライアントの Group Container がそのまま残存していた
  • [2b] IDE・開発キャッシュクリアを追加 — VSCode のログセッション・CachedExtensionVSIXs（30日以上前）と venv 内 __pycache__（毎週削除・自動再生成）を対象に。旧バージョンの拡張機能インストーラが蓄積しやすく、放置すると200MB超になる

やってみてわかったこと

  • キャッシュは放置すると驚くほど溜まる。Google Chrome だけで 3.8GB に達していた
  • Application Support には削除済みアプリの残骸が残ることが多い（Kobo・Filmora など 2GB 超）
  • .command ファイルは初回実行時にセキュリティ確認が出るが「開く」で通過すれば以降は不要
  • 削除対象の選定が一番大事。プロジェクトファイルに触れると取り返しがつかない
  • du -sm で Before/After を測ると達成感があり、次回実行への動機になる

今後やりたいこと

  • node_modules / .next など開発キャッシュの自動削除（最終更新日から N 日経過したものを対象に）
  • 通知センターへの完了通知（osascript で macOS ネイティブ通知）
  • 削除ログをグラフ化して週次の節約推移を可視化
