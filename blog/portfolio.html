Claude Code と壁打ちしながらポートフォリオサイトを作った話

デザインシステムの設計からレスポンシブ対応、ASCIIアニメーション実装まで、Claude Codeとの対話だけで完結させた。コードを書いた経験がほぼない状態から、このサイトが動くまでの記録。

--bg: #0a0a0f;
--ink: #e2e8f0;
--green: #48bb78;
--sans: 'Inter Tight';
--mono: 'JetBrains Mono';

なぜポートフォリオを作ったか

4つのプロダクトを作っても、見せる場所がなかった。GitHubのREADMEでは伝わらないし、口頭で説明するにも限界がある。「動いているものを見せる」ためのハブが欲しかった。

同時に、サイトそのものを5番目のプロダクトとして位置づけることにした。作り方も含めて見せられるなら、それが一番正直だと思った。

どうやって作ったか

コードエディタはほぼ開かず、Claude Codeとのチャットで進めた。デザインの方向性を言葉で伝え、生成されたコードを確認し、気になる点を指摘してまた修正する。この繰り返しだけで完成した。

方向性を言葉で伝える → CSS / HTML 生成 → ブラウザで確認 → フィードバック → 修正

一番時間がかかったのはデザイン方針の言語化だった。「エディトリアル系のwarm dark」から始まり、「ハイエンドSaaS（Linear / Vercel系）のニュートラルダーク」に着地するまで、何度も方向転換した。

デザインシステムの構築

最初にCSS変数（デザイントークン）を定義するところから始めた。色・フォント・ボーダーをすべて変数に集約しておくことで、後からテーマを丸ごと変えることができる。 

:root {
  --bg:    #0a0a0f;
  --ink:   #e2e8f0;
  --green: #48bb78;
  --sans:  'Inter Tight', sans-serif;
  --mono:  'JetBrains Mono', monospace;
}

フォントは2種類に絞った。Anton・Instrument Serif・Noto Sans JPを使っていた時期もあったが、情報量が増えるほど読みにくくなった。Inter Tight（見出し・本文）とJetBrains Mono（ラベル・コード）だけで十分だとわかった。

ASCIIアニメーションの仕組み

ヒーローセクションとWorksカードのカバーに、Canvas APIを使ったASCII文字のアニメーションを入れた。仕組みはシンプルで、グリッド状に文字を並べ、サイン波でアルファ値を変化させるだけ。

  • ヒーロー：マウス位置に反応して近くの文字が明るくなる
  • Worksカード：各プロジェクトのテーマカラーで異なる文字セットが流れる
  • IntersectionObserverでビューポート外はRAFを止めてパフォーマンスを確保

苦労したこと

スクロールトラップ問題

横スクロールのWorksレール実装で、縦スクロールがそのままWorksに吸われてしまう問題が起きた。wheelイベントでレールの端（atStart / atEnd）を判定して、端に達したらpreventDefault()しない、という処理で解消した。

デザインの方向転換

最初のデザインはamber warm（#1c1810ベース）の装飾的なスタイルだった。見た目は面白いが、プロフェッショナルな印象を与えたい場合には合わないと判断し、ニュートラルダークに全面変更した。CSS変数を使っていたおかげで、ルートの変数を書き換えるだけで大半の色が変わった。

学んだこと

  • 言語化が全て：Claude Codeへの指示が曖昧だと、生成されるコードも曖昧になる。デザインの意図を言葉にする力が一番重要だった
  • 変数設計を最初に：CSS変数を最初にちゃんと設計しておけば、後の大規模な変更も恐れなくなる
  • 作りながら決める：完璧な仕様書を作ってから実装するより、動くものを見ながら判断を積み重ねる方が早い

現在の構成

HTML / CSS / JavaScript のみ。フレームワーク不使用。ファイル構成はシンプルで、index.html・profile.html・style.css・script.js・blog/*.htmlだけ。

サーバーもビルドも不要なので、変更してブラウザをリロードすればすぐ確認できる。この軽さが気に入っている。
