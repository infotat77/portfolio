Next.js + Supabase で AWS SAA クイズアプリを作った話

AWS 認定ソリューションアーキテクト（SAA）の試験勉強をしながら、「どうせなら自分でクイズアプリを作って学ぼう」と思い立ち開発しました。 Next.js App Router・Supabase・Google認証・Vercelデプロイまで一気通貫で実装した記録です。

なぜ作ったのか

AWS SAA の試験勉強を始めたとき、市販の参考書や既存の問題サービスを使っていましたが、 「自分で問題を設計して実際に動くアプリを作れば、技術の学習と試験勉強を同時に進められる」と考えました。 サービスを使う側から作る側になることで、よりAWSの構成を深く理解できるという狙いもありました。

技術スタック

モダンなフルスタック構成を採用しました。フロントエンドからDB・認証・デプロイまで一貫して実装しています。

役割技術
フレームワークNext.js 16（App Router）
言語TypeScript
スタイリングTailwind CSS + shadcn/ui
データベースSupabase（PostgreSQL）
認証Supabase Auth（Google OAuth）
デプロイVercel

実装した機能

難易度・出題数のカスタマイズ

初級・中級・上級・すべての4段階と、5問・10問・20問の出題数を組み合わせて選択できます。 問題はランダムにシャッフルされるため、同じ設定で何度解いても違う問題が出題されます。

解説付きのクイズフロー

選択肢を選ぶと即座に正誤が表示され、正解の色付け（緑・赤）と解説文が表示されます。 合格ライン（72%）を意識したスコア表示で、弱点を把握しやすいUI設計にしました。

Google ログインと回答履歴

Supabase Auth を使った Google OAuth を実装しました。ログイン中のユーザーは回答が自動保存され、 マイページで難易度別の正答率と直近10問の回答履歴を確認できます。 未ログインでも問題を解けるため、試験前の手軽な確認にも使えます。

103問の問題データ

IAM・S3・EC2・RDS・Aurora・VPC・CloudFront・Lambda・ECS/Fargate・DynamoDB・ Kinesis・SQS/SNS・CloudWatch・GuardDuty・WAF・Cognito・Step Functions・ Athena・Redshift・DR戦略・コスト最適化・移行戦略など幅広い分野から103問を収録しています。

工夫した点

Supabase RLS によるデータ保護

PostgreSQL の Row Level Security（RLS）を設定し、「問題データは全員が読める」「回答履歴は本人のみ参照・保存可能」 というアクセス制御を実装しました。SQLポリシーで制御するため、アプリコード側で認証チェックを忘れても DBレベルで保護されます。 

-- 問題は全員閲覧可
create policy "問題は全員閲覧可" on questions
  for select using (true);

-- 回答は本人のみ
create policy "自分の回答のみ閲覧可" on user_answers
  for select using (auth.uid() = user_id);

Next.js App Router の useSearchParams 対応

Next.js 16 では useSearchParams() を使うコンポーネントを Suspense でラップしないとビルドエラーになります。 クイズページと結果ページの両方でこの対応が必要で、コンポーネントを分割して Suspense でラップする設計にしました。 

export default function QuizPage() {
  return (
    <Suspense fallback={<div>読み込み中...</div>}>
      <QuizContent />
    </Suspense>
  )
}

リリース後のセキュリティ改善

Vercel へのデプロイ後、コード全体をセキュリティの観点で見直しました。 「動くものを作る」段階から「安全に公開する」段階へのリファクタリングです。

正解をクライアントに渡さない設計に変更

最初の実装では、Supabase からクイズの問題データを取得するとき correct_answer フィールドも含めて クライアントに返していました。これだと開発者ツールで通信を確認するだけで全問の正解がわかってしまいます。

対策として API ルートを2本追加しました。/api/questions は正解フィールドを除いた PublicQuestion 型のみを返し、/api/check-answer は選択肢をサーバー側で検証して 正誤と解説だけをレスポンスします。これにより、クライアントは選択後にはじめて正解を知ることができます。 

// /api/questions — 正解フィールドを除いて返す
.select('id, question, choice_a, choice_b, choice_c, choice_d, difficulty')

// /api/check-answer — サーバー側で正誤判定
const correct = answer === question.correct_answer
return NextResponse.json({ correct, correctAnswer, explanation })

スコアの URL パラメータ渡しをやめた

最初は /result?score=8&total=10 のように URL でスコアを渡していました。 これだと URL を直接書き換えれば任意のスコアを表示できます（実害はありませんが）。 sessionStorage に保存して /result に遷移する方式に変更し、 URL から直接アクセスした場合はトップにリダイレクトするようにしました。 

// クイズ終了時
sessionStorage.setItem('quizResult', JSON.stringify({ score, total }))
router.push('/result')

// 結果ページ
const raw = sessionStorage.getItem('quizResult')
if (!raw) { router.replace('/'); return }

マイページを Server Component に変換

/mypage はログイン必須のページですが、もともと Client Component で useEffect 内で認証チェックをしていました。この実装だと、 未ログインユーザーが一瞬コンテンツを見てからリダイレクトされる可能性があります。 Server Component に変換し、redirect() でサーバー側で即座に弾くようにしました。 

export default async function MyPage() {
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()
  if (!user) redirect('/')  // サーバー側で即リダイレクト
  // ...
}

セキュリティヘッダーの追加

next.config.ts に HTTP セキュリティヘッダーを設定しました。 クリックジャッキング防止・MIME スニッフィング防止・リファラー情報の制限などを全ルートに適用しています。 

async headers() {
  return [{
    source: '/:path*',
    headers: [
      { key: 'X-Frame-Options', value: 'DENY' },
      { key: 'X-Content-Type-Options', value: 'nosniff' },
      { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
    ],
  }]
}

その他の細かい修正

  • URLパラメータ（difficulty・count）を許可リストでバリデーション
  • Supabase クエリの error を無視していた箇所にエラーハンドリングを追加
  • シャッフルを Math.random() - 0.5（分布が偏る）から Fisher-Yates アルゴリズムに変更
  • <img> を Next.js の <Image> に変更し、外部ドメインを allowlist で管理
  • Next.js 16 の proxy.ts 規約に合わせて非推奨の middleware.ts を削除

詰まったポイントとデバッグの話

Vercel の環境変数が空になっていた

デプロイ後に友人に試してもらったら「問題が表示されない」と言われました。 Supabase のデータや権限設定は問題なく（set local role anon; select count(*) from questions; で103問確認）、 原因を探ると Vercel に登録した環境変数の値が空文字になっていました。 vercel env pull --environment=production で確認して発覚し、正しい値で再登録・再デプロイして解決しました。

Supabase の GRANT 設定

RLS ポリシーで using (true) と書いても、anon ロールへの GRANT SELECT が付与されていないと未ログインユーザーがデータを読めません。 スキーマ作成時に以下を追加することで解決しました。 

GRANT SELECT ON questions TO anon;
GRANT SELECT ON questions TO authenticated;

重複データの削除

SQLファイルを複数回実行してしまい、問題が重複して登録されました。 min(uuid) は PostgreSQL では使えないため、row_number() を使った 重複削除クエリで解決しました。 

delete from questions where id in (
  select id from (
    select id, row_number() over (
      partition by question order by created_at
    ) as rn from questions
  ) t where rn > 1
);

やってみてわかったこと

  • Next.js App Router は Pages Router と設計思想が大きく異なるため、公式ドキュメントを先に読むことが重要
  • Supabase は RLS + GRANT の組み合わせで細かいアクセス制御ができ、Firebase より SQL に近い感覚で扱える
  • Vercel の環境変数は NEXT_PUBLIC_ プレフィックスを付けるとビルド時にバンドルされるため、デプロイ前に値を確認する習慣が必要
  • 問題を103問自分で設計したことで、AWS の各サービスの用途と違いが体系的に頭に入った
