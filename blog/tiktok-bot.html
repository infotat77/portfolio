2026.06.06 Python TikTok API 自動化

投資系ショート動画をTikTokに自動投稿するシステムを作った話

NISA・高配当株などの投資コンテンツ動画を、スケジュール管理しながらTikTokへ自動投稿するシステムを作りました。 TikTok Content Posting API（Direct Post）を使い、OAuthトークンの自動リフレッシュ・チャンクアップロード・ 重複投稿防止まで一通り実装。launchdで毎日19時に自動実行されます。

なぜ作ったのか

NISAや高配当株などの投資コンテンツをTikTokで発信したいと考えていました。 しかし毎日手動で投稿するのは続かない。だったら仕組みごと作ってしまえ、というのが出発点です。 YouTube自動投稿（焚き火ボット）で得たノウハウをTikTokに横展開しました。

パイプライン全体像

1回の実行で以下が自動で行われます。

videos.json → 期限チェック → Token取得 → API init → チャンク送信 → 完了確認 → ログ記録

実装で工夫した点

OAuthトークンの自動リフレッシュ

TikTokのアクセストークンには有効期限があります。 auth.py でトークンの期限切れを事前に検知し（期限5分前）、 リフレッシュトークンを使って自動更新。更新されたトークンは .env に書き戻すため、 次回起動時も引き継がれます。 

def is_token_valid(self, buffer_seconds: int = 300) -> bool:
    return time.time() < (self.expires_at - buffer_seconds)

チャンク分割アップロード

TikTok APIは大きな動画ファイルをそのまま送れないため、10MB単位に分割して Content-Range ヘッダーを付与しながら順番にPUTします。 ショート動画なら1〜2チャンクで完了します。 

headers = {
    "Content-Type": "video/mp4",
    "Content-Range": f"bytes {start}-{end}/{video_size}",
    "Content-Length": str(len(chunk_data)),
}

重複投稿防止

videos.json の status フィールドと、 別ファイル posted_log.json の両方でIDを照合します。 万が一 videos.json が手動編集されても、 posted_log.json 側で二重チェックが働きます。

審査前は強制的にSELF_ONLY

TikTok Content Posting APIは審査（audit）通過前は投稿が非公開扱いになります。 プライバシー設定は config.py の PRIVACY_LEVEL 定数で一元管理しており、 審査通過後に "PUBLIC_TO_EVERYONE" へ変更するだけで全投稿に反映されます。

ディレクトリ構成

tiktok_bot/
├── main.py          # エントリーポイント（--dry-runオプション付き）
├── poster.py        # TikTok API投稿（init → upload → status確認）
├── auth.py          # OAuthトークン管理・自動リフレッシュ
├── scheduler.py     # 投稿キュー管理・重複防止
├── config.py        # 設定定数（PRIVACY_LEVELはここ）
├── data/
│   ├── videos.json       # 投稿スケジュール管理
│   └── posted_log.json   # 投稿済み記録
├── videos/          # 動画ファイル（.gitignore対象）
└── scripts/
    └── com.tat.tiktokbot.plist  # launchd設定

ドライランで事前確認

実際に投稿せず、投稿対象・設定内容だけを確認できる --dry-run モードを用意しています。 新しい動画を追加したあとは必ずドライランで確認してから本番実行しています。 

python3 main.py --dry-run

# 出力例

  ID       : 001
  ファイル : videos/nisa_intro.mp4
  タイトル : 【NISA完全解説】新NISAの賢い使い方

  プライバシー: SELF_ONLY

やってみてわかったこと

  • TikTok APIの審査は申請から最長10営業日かかる。コンテンツカテゴリが「金融・投資」だとより丁寧な説明が必要
  • Direct Post方式はファイルを直接アップロードするため、URLプル方式より実装が複雑だが、外部公開URLが不要なのでローカル運用に向いている
  • 投稿ステータスは非同期確認。PROCESSING_UPLOAD → PUBLISH_COMPLETE まで数秒〜数十秒かかる
  • OAuthのリダイレクトURIは開発時は https://localhost/callback で問題なかった
