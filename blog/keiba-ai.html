2026.05.27 Python 機械学習 LightGBM

PythonとLightGBMで競馬予測AIを作った話

JRAの過去レース結果・オッズ・ラップタイムを含む約160万行のデータをLightGBM / CatBoost / XGBoostで学習し、 馬の勝率を予測するシステムを作りました。Streamlitで予想印と回収率シミュレーションを見られるWebアプリまで一気通貫で。

なぜ作ったのか

競馬予想サイトは「根拠が不透明」「過去の的中実績が検証できない」ものが多い。 ならば自分でデータを集めてモデルを作り、再現性のある予測基盤を持つほうが面白い。 機械学習の実践の場としても、160万行規模のデータと明確な評価指標（的中率・回収率）が揃う競馬はうってつけでした。

データと前処理

使用したのは1986〜2021年のJRAレース結果・オッズ・ラップタイム・コーナー通過順の4CSV。 前処理後の特徴量は約160万行になります。

生CSV（4種） → 結合・欠損処理 → 特徴量エンジニアリング → features.csv（160万行） → モデル学習

学習データは1986〜2018年、検証データは2019〜2021年と時系列で分割しました。 レース結果を「1着 or それ以外」の2値分類問題として定式化しています。

使用したモデル

モデル特徴
LightGBM学習速度が速くチューニングの試行回数を稼ぎやすい。ベースラインとして採用
CatBoostカテゴリ変数（競馬場・馬名・騎手）の扱いが得意でそのまま投入できる
XGBoost汎化性能の補完目的。オッズなし版も含めて合計6モデルを学習

オッズを特徴量に含めた版と含めない版の両方を用意しました。 オッズは市場の集合知であり強力な予測因子ですが、「オッズなしでどこまで予測できるか」も検証したかったためです。

モデル性能（検証データ: 2019〜2021年）

0.8303 AUC
33.4% 的中率
82.0% 回収率

回収率82%はJRAの控除率（約25%）の壁があるため100%を下回っています。 ただしランダム予測（的中率は出走頭数の逆数）に対してAUC 0.83はモデルとして機能している証拠です。

StreamlitでWebアプリ化

予測結果をCLIで見るだけでは使いにくいので、Streamlitでインタラクティブなダッシュボードを作りました。

  • サイドバーで「年 → 開催場所 → レース番号」を選択するとその出走馬の予想印・勝率が表示される
  • ◎（本命）〜×（その他）の予想印を自動付与
  • 画面下部に検証期間（2019〜2021年）の回収率推移グラフをプロット
# 予想印の付与ロジック
rank_to_mark = {1: '◎', 2: '○', 3: '▲', 4: '△'}
df['mark'] = df['rank'].map(rank_to_mark).fillna('×')

実装で工夫した点

Optunaでハイパーパラメータ探索

LightGBMとXGBoostはOptunaで100trial以上探索しました。 最適パラメータは best_params.json に保存して再現できるようにしています。

オッズありなし2バージョン

オッズは情報として強力すぎるため「純粋なデータ力」を測るためオッズなし版を別途学習。 モデルファイルは lgbm_model.pkl と lgbm_model_no_odds.pkl の2本体制です。

SQLiteで予測結果を管理

毎回CSVを再読み込みするのは非効率なので、前処理済みデータと予測ログを keiba.db（SQLite）に格納。 cronで週次更新する weekly_update.py も作りました。

やってみてわかったこと

  • 競馬の予測は「勝馬を当てる」より「回収率を最大化する」ことが目標と気づいた（的中率より賭け方の設計が大事）
  • CatBoostはカテゴリ変数のエンコードが不要で実装がシンプルになった
  • Optunaの並列探索（n_jobs=-1）は大規模データで体感できるほど速い
  • 時系列データは「未来のデータで学習して過去を予測しない」よう分割に注意が必要
  • 回収率82%は「負け越しているが市場平均よりはマシ」という微妙なポジション
