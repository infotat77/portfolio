YAMAHA RTX810 のセキュリティ強化と VPN 構築をした話

自宅の YAMAHA RTX810 ルーターが脆弱な初期設定のまま運用されていたので、Telnet 無効化・SSH 有効化・ファイアウォール強化・VPN 設定まで一気にやり直した。途中で WN-DX1200GR が RTX810 を勝手に書き換えていた事件も発覚し、ルーターまわりの複雑さを身をもって体験した記録。

背景

自宅ネットワークに YAMAHA RTX810 を導入していたが、初期設定のまま長期間運用していた。 Telnet が有効・pp 1 にセキュリティフィルターなし・アウトバウンドが実質全許可という状態だったため、 一通り見直すことにした。

発見した脆弱性

項目問題
Telnet有効（平文通信）
pp 1セキュリティフィルター未設定・常時接続
アウトバウンドdynamic 201098/201099 で TCP/UDP 全許可
管理パスワード1文字の極端に短いパスワード
WN-DX1200GR「おまかせ設定」でRTX810設定を無断変更していた

対応した内容

Telnet 無効化 → SSH 有効化

WebGUI のコマンド実行から no telnetd host lan を実行。 続けて SSH を sshd host lan1 で有効化し、ホスト鍵を生成した。 sshd host lan だとエラーになる点に注意（lan1 と明示する必要がある）。 

no telnetd host lan
sshd host lan1

pp 1 の無効化

デフォルトゲートウェイは pp 2（ソフトバンク光）のみで、pp 1 は未使用だったため無効化した。 

pp select 1
pp disable 1

管理アクセスの制限

WebGUI と SSH を自分の Mac（192.168.10.100）とデスクトップ PC（192.168.10.2）のみに制限した。 後述の WN-DX1200GR 問題の根本対策でもある。 

httpd host 192.168.10.100 192.168.10.2
sshd host 192.168.10.100 192.168.10.2

WN-DX1200GR 事件

作業中にルーターが何度も無応答になる現象が発生した。ログを確認すると、LAN 内の 192.168.100.2 というデバイスが管理者として複数回 WebGUI にログインし、設定を書き換えていた。 

Login succeeded for HTTP: 192.168.100.2
'administrator' succeeded for HTTP: 192.168.100.2
Configuration saved in "CONFIG0" by HTTPD

MAC アドレスを調べると ASIX Electronics（USB-LAN アダプターチップのメーカー）で、 正体はポート 3 に接続している I-O DATA WN-DX1200GR の WiFi アクセスポイントだった。 「おまかせ設定」という機能が上流ルーターに自動アクセスして設定を変更する仕様になっていた。

AP を工場出荷状態にリセットし、RTX810 側で管理アクセスを IP 制限することで「おまかせ設定」問題は解消した。 ただしリセット後、WN-DX1200GR がルーターモードで起動し、独自の 192.168.0.x サブネットで DHCP を配布する状態になっていた。 これにより二重 NAT が発生し、WiFi 接続はできるもののインターネットに出られない状態が続いていた。

後日、工場出荷状態の WN-DX1200GR の管理画面（http://192.168.0.1）にアクセスして 動作モードをルーターモードから AP モード（アクセスポイントモード）に変更することで完全解決した。 APモードでは WN-DX1200GR は単純な無線ブリッジとして動作し、 WiFi クライアントは RTX810 の DHCP から直接 192.168.10.x のアドレスを取得できるようになった。

L2TP/IPsec VPN 設定

外出先からのアクセスを目的に L2TP/IPsec VPN を設定した。 macOS のビルトイン VPN クライアントから接続できる構成。 

ipsec ike version 1 1
ipsec ike encryption 1 aes-cbc
ipsec ike hash 1 sha
ipsec ike pre-shared-key 1 text [PSK]
ipsec ike remote address 1 any
tunnel select 1
  tunnel encapsulation l2tp
  ipsec tunnel 101
l2tp service on
pp select anonymous
  pp bind tunnel1
  pp auth username [user] [pass]
  ip pp remote address pool 192.168.10.200-192.168.10.210

CGNAT の壁

設定完了後、テザリングから VPN 接続を試みたが繋がらなかった。 原因を調べると、ソフトバンク光は CGNAT 環境であり、グローバル IP（221.103.230.95）が 複数ユーザーで共有されていた。テザリングしたスマホも同じ IP になるため、 「外部から自宅ルーターに接続する」ことができない構造だった。

IPv6 IPoE への切り替えも試みたが、インターネット疎通まであと一歩届かず（ソフトバンク光の IPv6 オプション未契約が原因と思われる）。

Tailscale で解決

CGNAT を回避できる Tailscale を導入した。 各デバイスにアプリをインストールするだけで、NAT 越えを自動処理してくれる。 無料プランで 100 デバイスまで接続でき、管理画面も使いやすい。

方式CGNAT対応設定難易度
L2TP/IPsec不可高
IPv6 VPN可（ISP対応要）高
Tailscale可低

やってみてわかったこと

  • ルーターのログは宝の山。問題の原因がほぼすべてログに記録されていた
  • WiFi AP の「おまかせ設定」は便利な反面、意図しないルーター設定変更を引き起こすことがある
  • AP を工場出荷リセットするとルーターモードで起動するため、二重 NAT になる。AP モードへの変更を忘れずに
  • ソフトバンク光は CGNAT。L2TP/IPsec VPN を使いたいなら IPv6 オプション契約が必要
  • RTX810 のコマンドは SSH 越しの非インタラクティブ実行（ssh host "cmd"）に非対応
  • sshd host lan はエラー。sshd host lan1 と書く必要がある
  • Tailscale は CGNAT 環境での VPN 代替として非常に優秀

追記（2026.05.31）: DHCP IP 変動でアクセス不能になった話

設定完了後、しばらくして RTX810 に SSH も WebGUI も繋がらなくなる事態が発生した。 原因は単純で、Mac に DHCP で割り当てられた IP が 192.168.10.100 から 192.168.10.12 に変わっていたのが原因だった。 SSH・HTTP アクセスを .100 と .2 に制限していたため、そのまま弾かれていた。 ping は通るのに SSH できないのが最初のヒントになった（ICMP はフィルター対象外）。

復旧手順は以下の通り。Mac の IP を手動で 192.168.10.100 に設定して SSH で入り、 DHCP スコープバインドを設定して保存した。 

administrator
dhcp scope bind 1 192.168.10.100 ethernet aa:39:d2:5e:ab:f0
save

これで Mac の MACアドレス（aa:39:d2:5e:ab:f0）には常に 192.168.10.100 が割り当てられるようになった。Mac 側は DHCP のままでよく、手動 IP 設定は不要になった。

あわせて ~/.ssh/config にキープアライブ設定を追加した。RTX810 は SSH セッションが アイドル状態になるとすぐ切断されるためで、これがないと接続直後に落とされることがある。 

Host rtx810
    HostName 192.168.10.1
    User EnURA1201
    KexAlgorithms +diffie-hellman-group14-sha1
    HostKeyAlgorithms +ssh-rsa
    ServerAliveInterval 30
    ServerAliveCountMax 10

IP 制限によるロックアウトを防ぐには、管理 PC に DHCP 固定割り当てをしておくのが必須だと改めて実感した。 アクセス制限をかけるなら IP が変わらないことを前提にする必要がある。
